# Memory-Hook Learning Doctrine V1

## Core idea

The studio does not use characters as decoration placed on top of technical ideas. The characters are memory hooks for the real function of the idea.

A child should be able to move through this chain:

**symbol or concept -> character -> story -> remembered action -> real technical meaning**

The cartoon is successful when the child can later retrieve the correct technical idea because the character and story made it memorable.

## Non-negotiable rule

A character's story behavior must remain faithful to the real behavior of the symbol, concept, operation, or reasoning tool it represents.

Do not give a character arbitrary powers that contradict or distract from the underlying concept.

Examples:

- Percy / parentheses: groups related material, changes how grouped material is read or evaluated, keeps related things together. Percy does not gain unrelated magic powers.
- Brac / brackets: groups, contains, and distinguishes nested or special structures in ways consistent with the technical context being taught.
- Curly / braces: represents larger grouping, blocks, sets, scopes, or collections only where that mapping is technically appropriate.
- Don Sol: represents disciplined inquiry rather than a symbol. His recurring prompts are cognitive tools: "What do we actually know?", "What are we assuming?", "What don't we know yet?", and "Now that's a better question."

## Educational objective

The learner should eventually be able to encounter code, mathematics, logic, science, or a game mechanic and think in remembered story language before translating that memory into the formal concept.

Example retrieval cues:

- "Percy needs to hold this together."
- "This group is nested inside that group."
- "I need to separate what I saw from what I think."
- "What don't I know yet?"

Those cues are useful only if they lead to the correct technical behavior.

## Design test for every new character

Before approving a new educational character, answer:

1. What real concept does this character represent?
2. What does that concept actually do?
3. What actions can the character perform that are faithful to that function?
4. What actions are forbidden because they would teach the wrong mental model?
5. What recurring story situation makes the concept easy to retrieve later?
6. Can the child eventually move from the character metaphor back to formal notation or terminology?

If the answers are weak, the character is not ready.

## Design test for every episode or game

Every story, cartoon, puzzle, or game should preserve this sequence:

1. A real problem appears.
2. The character's native function becomes relevant.
3. The character acts in a way consistent with the underlying concept.
4. The learner sees a consequence that makes sense.
5. The formal idea can later be named without contradicting the story.

## Cross-platform rule

The same memory hook must mean the same thing everywhere:

- cartoon
- game
- website guide
- book
- classroom activity
- coding or math environment

Do not let gameplay convenience or comedy redefine a character's core technical meaning.

## Long-term ambition

The studio should create childhood memories that remain useful years later.

A teenager debugging code, solving a math problem, or evaluating a claim should be able to remember a character, a scene, or a question and use that memory to recover the correct structure or reasoning move.

The goal is not merely recognition.

The goal is **transfer**.

A successful character eventually disappears into the learner's own thinking.
